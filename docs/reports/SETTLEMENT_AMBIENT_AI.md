# 集落の暮らし（場所が人を動かす）の実装報告

## 実行結果

`site/settlement.html` を追加した。上から見た集落で、人が場所へ集まり、使い、しばらくして立ち去る。狩猟採集・農耕・都市の3時代を切り替えられる。入口（`site/index.html`）のリンク一覧から開ける。

Unity版へは移さず、ブラウザだけで完結するページとした（オーナー判断、2026-10-03）。Unity版の地表に立つ人は、従来どおり静止したままである。

## 仕組み

ゲームAIでいう「アンビエントAI」の考え方を使う。知能を一人ひとりの中ではなく、場所の側に置く。

| 部品 | 役割 |
|---|---|
| 欲求 | 人ごとに「食・水・休・語」の4つがあり、時間とともに増える |
| 場所（スマートロケーション） | 席の数を持ち、その場所でできる行動の札が結びつく。例：焚き火では「肉を焼く」「火を囲んで語る」ができる |
| 行動の札 | 「前提の持ち物 → 行動 → 結果の持ち物・満たす欲求」を1枚にまとめたもの。どの場所で行うかも持つ |
| 連鎖プランニング | いちばん高い欲求を目標にし、札の結果と次の札の前提が合うようにつないで、最大4手の手順を組む。移動距離と所要時間が小さい手順を選ぶ |
| 寄り道の禁止 | 途中で手に入れた物は、あとの手でかならず使う。すでに持っている物は取りに行かず、持てるのは3つまで |
| 席の予約 | 手順を一手進めるごとに、その場所の空き席を予約して向かう。最初の一手の場所が満席の手順は採らない |
| 最後の一手 | 手順の最後の札は、目標の欲求を十分に（0.5以上）満たすものに限る。「語りたい人が肉を食べに行く」ような的外れな手順を防ぐ |
| 待ちと組み直し | 一番よい手順の場所が満席でも、待つ人が席の3分の1未満なら、そこで待つ。途中の場所が満席なら近くで7秒待ち、空かなければ持ち物を持ったまま手順を組み直す。組み直した直後は待たずに空いている所を選ぶ |
| 立ち去り | 着いた時点で「何秒後に立つか」を決め、その時刻に持ち物を入れ替えて席を返す |
| 会話の進行役 | 同じ場所に2人以上いると、話し手を順番に回し、他の人は相槌を打つ |

## 画面（AI Graph風）

ゲームAIの開発ツール「AI Graph」の見せ方にならい、左（スマホでは下）に観察している人の頭の中、右（スマホでは上）に集落を並べる。

| 区画 | 見せるもの |
|---|---|
| 身体の状態 | ぶらつく → 向かう → 待つ → 使う のうち、いまの状態を青く光らせる（ステートマシン） |
| 目標と計画 | 目標の欲求と、手順の札を「前提（青）→ 行動（橙）→ 結果（青）」の形で横につなぐ。済んだ札は薄く、実行中の札は青く光らせ、進み具合の棒を付ける |
| 黒板 | 4つの欲求の高さと、持ち物 |
| 検討した手順 | 計画を立てたときに比べた候補（最大4つ）と費用。選んだ手順に印を付ける |
| 実行ログ | 集落全体の「前提 → 行動 → 結果」 |

観察する人は、人をタップすると固定され、何もない所をタップすると「自動で追う」に戻る。自動で追うときは、いちばん長い手順を進めている人を選び、3手以上の手順を進めている間は乗り換えない。集落の側にも、観察している人のこれからの道順を番号付きの線で描く（実行中は青、その先は紫の点線）。人の横の小さな粒は持ち物。「席と欲求」で、席の空き状況と一人ひとりの欲求が見える。

## 視点

ドラッグで移動、マウスのホイール・2本指のピンチ・＋−ボタンで拡大縮小（最大5倍）。「カメラで追う」で観察している人にカメラが付いていき、「全体」で元に戻る。動かさずに離したときだけタップとして扱い、人を選ぶ。

動かない部分は時代を切り替えたときに一度だけ下絵として描き、毎フレームは炎・煙・水・人・光だけを描く。

## 3D表示

集落の枠の「3D」で、立体の地図に切り替わる（Three.js が読み込めたときは最初から3D）。シミュレーションは2Dと同じものを使い、見せ方だけを変える。2Dに戻すと、同じ人・同じ状態のまま平面で見られる。

| 対象 | 作り |
|---|---|
| 地形 | 2Dと同じ地面の絵を貼った起伏のある地面。場所の周りは平らにし、縁へ向かって上がる。地図の外は丘と森が続き、遠くに雪をかぶった山並み、空と霧 |
| 場所 | 焚き火（石囲み・座る丸太・揺れる炎・灯り・煙）、川の水面、木の実の茂み、テントと干し肉の棚、麦畑と柵、石臼（使うと柄が回る）、かまど（灯り・煙）、井戸、茅葺きの家と縁台、工房と酒場、縞の日よけの屋台、噴水、列柱の神殿と浮かぶ水晶。木は2Dと同じ位置に立つ |
| 人 | 関節で動く立体の人。装いは2Dと同じ役目ごとのオリジナル（剣士・魔導士・神官・狩人など）。歩くと脚と腕が交互に振れ、場所では座り、働く札では腕を振る。持ち物は右手に持ち、2つ目からは足もとに置く |
| 光 | 太陽が動き、影が伸びる。夜は青白い月明かりになり、焚き火・かまど・家の窓・神殿の水晶が灯る |
| カメラ | ドラッグで回り込み、ホイール・ピンチ・＋−で寄る。右ドラッグ・Shift＋ドラッグ・2本指で平行移動。「カメラで追う」で観察している人の後ろへ低く回り込む。タップで人を選ぶ |
| 道順と印 | 観察している人の道順を、地面の上の線と番号で示す。場所の名前は常に読める大きさで表示し、「席と欲求」では席の空き（白・橙）を地面に示す。欲求の棒は2Dだけ |

### 外部ライブラリ

3D表示のため、Three.js r158（MITライセンス）の `build/three.min.js` を `site/vendor/three.min.js` に同梱した（オーナー承認、2026-10-04）。ライセンス文は `site/vendor/three.LICENSE.txt`。CDNは使わない。r158の単体ファイルは読み込み時に「将来のr160で廃止」という注意を出すが、動作には影響しない。読み込めないときは「3D」ボタンが押せなくなり、2Dで動く。

## 時代ごとの場所と、食べるまでの手順

| 時代 | 場所 | 食べるまでの手順（例） |
|---|---|---|
| 狩猟採集 | 焚き火、川辺、木の実の茂み、獲物の解体場 | 肉を切り分ける → 肉を焼く → 焼いた肉を食べる（3手）／実を採る → 木の実を食べる（2手） |
| 農耕 | 畑、石臼、かまど、井戸、家の前の縁台 | 麦を刈る → 粉にひく → パンを焼く → パンを食べる（4手） |
| 都市 | 工房、市場、噴水、神殿の階段、酒場 | 工房で働く → 料理を買う → 酒場で食べる（3手） |

時代が進むと、食べるまでの手順が「採る」から「育てて加工する」、さらに「働いて買う」へと変わる。手順の長さと形の違いで、暮らしの変化を見せる。

場所の顔ぶれと数値は象徴的な表現であり、史料から取った値ではない。

## 検証結果

- シミュレーション部分を画面なしで、3時代 × 人数3通り（6・18・40人）× 画面の向き2通りで、各10分ぶん回した。席の二重予約・前提の持ち物を持たないままの実行・持ち物の増え続け・予定時刻を過ぎた居残り・60秒以上着かない人・場外へ出る人はいずれも0件。全時代で全部の場所が使われ、2手以上の手順が組まれ、会話の進行も働いた。
- 途中で見つかって直した不具合：満席で組み直すと持っている物をまた取りに行き、持ち物が増え続けた（すでに持つ物は取りに行かない・3つまでに制限）。目的と無関係な寄り道（「実を採る → 水を飲む」など）が手順に混じった（手に入れた物はあとの手で使うことを条件に追加）。農耕の4手の手順が上限3手で組めなかった（上限を4手に変更）。
- ヘッドレスのChromiumで、スマホ幅（390px）とPC幅（1366px）を表示し、画面を撮って確認した。AI Graphに4手の計画が並び、実行中の札が光ること、集落に道順が描かれることを確かめた。スクリプトのエラーは0件。
- 途中で直した点：自動で追う人に1手だけの計画の人が選ばれ、連鎖が見えにくかった（長い手順の人がいれば乗り換えるよう変更）。
- 「語」を目標にした人が肉を食べに行く画面がオーナーから示された。原因は、最後の札が目標の欲求を少ししか満たさなくても手順に採っていたことと、一番よい場所が満席だと次善の手順へすぐ移っていたこと。最後の札の条件と、待つ・組み直すの規則を加えて直した。直したあと、3時代とも目標に弱い手順は0件、40人での組み直しは10分あたり約130〜200回（以前は約1100回）になった。
- 見た目を描き直したあと、同じ検証を再実行していずれも0件。ヘッドレスのChromiumで3時代の昼と、狩猟採集の夜を撮って確認した。スクリプトのエラーは0件。
- 描き直しの途中で、最初のフレームで経過時間が負になり得る不具合を見つけて直した（経過時間を0以上に制限）。
- 視点と人物を入れたあと、同じ検証を再実行していずれも0件。ヘッドレスのChromiumで、3時代の全体と「カメラで追う」での拡大を撮って確認し、ホイール・ドラッグ・タップでの選択が働くことを確かめた。スクリプトのエラーは0件。
- 3D表示を入れたあと、同じ検証を再実行していずれも0件。ヘッドレスのChromium（ソフトウェア描画）で、3時代の全体と「カメラで追う」、夜の焚き火、スマホ幅を撮って確認した。3Dでのタップによる選択、ドラッグで回り込むと「自動で追う」が外れること、2Dに戻してのタップ選択を確かめた。スクリプトのエラーは0件。ソフトウェア描画では毎秒数コマしか出ないため、実機での滑らかさは未確認。
- 実機（スマホ）での確認は、オーナーによるもの以外は未実施。ピンチ操作と3Dの描画速度は実機で未確認。
