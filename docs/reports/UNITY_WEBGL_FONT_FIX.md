## 不具合5：WebGLで日本語が1文字も出なかった

### 症状

ボタン15個とすべての説明文が空の四角になり、何の段階か読めない。

### 原因

`JapaneseFont` はOSの日本語フォントを動的に割り当てる方式だった。
WebGLにはOSのフォントが存在しないため、`Font.GetOSInstalledFontNames()` が空になり、
内蔵フォント（LegacyRuntime）へ落ちる。内蔵フォントに日本語の字は無い。

`JapaneseFont.cs` のコメントには既に
「OSに日本語フォントが無い環境では内蔵フォントへ落ち、日本語が出ない可能性がある」
と書かれていた。WebGLへ移した時点でこの既知の制限が現実になっていた。

実ブラウザのログでも確認した。

```
[UI] 日本語フォント: LegacyRuntime（内蔵へフォールバック）
```

### 対応

フォントを同梱する。ただし丸ごと入れると容量が増えるため、**出る文字だけを残した**。

- 元フォント：Noto Sans JP（`C:\Windows\Fonts\NotoSansJP-VF.ttf`、バージョン2.004）
- ライセンス：SIL Open Font License 1.1（再配布可）
- 9,590,844バイト → **461,112バイト（4.8%）**

残す文字は、出どころを全走査して決めた。

1. `Assets/StreamingAssets/*.json` と `site/data/*.json`
2. `Assets/Scripts/` と `Assets/Editor/` の C# ソース中の非ASCII文字
3. 取りこぼし対策として、印字可能ASCII・ひらがな全域・カタカナ全域・全角英数記号・よく使う記号

合計1,064文字（うち漢字663文字）。抜き出し後に全文字が入ったことを検査している。

作業中に2点つまずいた。記録しておく。

- この可変フォントの既定の太さは **100（Thin）** である。既定値で固定すると
  画面の文字が細すぎて読めない。本文用の400（Regular）で固定した。
- `≒`（U+2252）はNoto Sans JPに字が無い。アプリでも使っていないため要求から外した。

OFL 1.1 の条項3が定める Reserved Font Name は `Source` であり、
改変後の名前（`Noto Sans JP Subset`）はこれを含まない。
条項2に従い、著作権表示とライセンス全文を `Assets/Resources/Fonts/OFL.txt` と
`site/unity/OFL.txt` に同梱している。

### 結果

```
[UI] 日本語フォント: NotoSansJP-Subset（同梱）
```

ビルドの増加は **+273KB**（`unity.data` が 1,495,094 → 1,768,918 バイト）。
フォントを丸ごと入れた場合の +5.9MB に対して20分の1以下で済んだ。

### 作り直し方

新しい**漢字**をデータへ追加した場合は、フォントを作り直す必要がある。
かな書きなら作り直さなくても表示できる。

作り直しには `fontTools` を使った。リポジトリにはツールも元フォントも含めていない。
文字の集め方は上の1〜3のとおりで、`Assets/Resources/Fonts/NOTICE.md` にも記録している。

## 不具合6：WebGLで地球が単色の球に見える

### 症状

Editorでは大陸・海・植生が描かれるのに、WebGLでは一様な色の球になる。
時代によって色だけが変わる（マグマの地球は橙、森林と陸上生態系は緑）。

### 切り分け

半透明の殻を時間差で1枚ずつ外すビルドを作り、実ブラウザで撮影した。

| 外したもの | 見え方 |
| --- | --- |
| なし | 一様な緑の球 |
| 大気 | 一様な**白**の球（雲の殻） |
| 大気・雲 | **正しい地球**（緑の陸と青い海） |

つまり雲の殻と大気の殻が、半透明にならず**不透明な球として**描かれ、
いちばん外側の大気が地表を完全に覆っていた。

Standardは、半透明の枝が使われない場合、不透明度を1として出力する。
混ぜ方をSrcAlphaにしていても、元の不透明度が1なら結果は完全な不透明になる。
大気の不透明度 0.10 が効かなかったのはこのためである。

### 試して直らなかったこと

材質はすべて実行時に `new Material(Shader.Find("Standard"))` で組んでいた。
ビルドはプロジェクト内の材質に現れないキーワードの組み合わせを削るため、
実行時にしか存在しない組み合わせは残らない。これが原因だと考えて2つ試した。

1. **実行時に行き着く組み合わせを雛形の材質として資産に置く。**
   `_ALPHABLEND_ON` だけでなく、生成後に `AssignSurface` が立てる `_NORMALMAP` まで
   含めた6通りを `Assets/Resources/Materials/` に置いた。
   雛形は読めている（警告なし）が、**WebGLの症状は変わらなかった。**
2. **半透明を専用シェーダーへ移す。**
   キーワードで分岐しないシェーダーなら削られない。描き方は実際に変わったが、
   Standardの見え方に揃えられず、Editorの絵が暗く濁ったため取り下げた。

したがって**原因はまだ確定していない。** 上の「Standardの半透明の枝が
ビルドに残らない」という見立ては、1が効かなかったことと整合しない。

### 採った回避策

WebGLでのみ、雲と大気の殻を出さない（`EarthView.HideShellsWhereBlendingIsUnavailable`）。
切り分けで、殻を外せば地表が正しく出ることを実機で確認したうえでの判断である。

- 得るもの：地球が単色の球ではなくなる。大陸・海・植生・都市光が見える
- 失うもの：WebGLでは雲と大気の輪郭光が出ない
- Editorと他の環境：これまでどおり。見え方は変えていない

「単色の球」より「雲と大気の無い地球」の方が良いと判断した。

### 本筋の直し方（未実施）

雲を地表の絵へ焼き込んでしまえば、半透明の殻そのものが要らなくなる。
`PlanetSurfaceBaker` 側の仕事になる。大気の輪郭光は、
球の外側へ向かうほど濃くなる不透明度を持つ専用シェーダーで描くのが素直である。

## 作業中に見つけて直した不具合

依頼された4点の実装中に、実際に動かさなければ気づけない不具合を2件見つけた。

1. **`MoonExpansionLoader` が段階数を4に固定していた。**
   5段階目を足した瞬間に月への展開データ全体が読込失敗し、月ビューが丸ごと消えた。
   `RequiredPhaseCount` を5へ。件数を固定しているのは段階の抜けに気づくためなので、
   定数は残して値だけ変えた。
2. **`sinceImpact` の加算が沈み込み処理の中にあった。**
   衝突天体が隠れる0.36秒で時計が止まり、**地球が永久に揺れ続けた。**
   加算を `Update()` へ移し、沈み込みと揺れが同じ時計を共有するようにした。

また、拠点の軌道半径を当初 1.55 にしていたが、地球の半径は 2.2 であり、
拠点が地球の内部に埋まる。3.5（R1の人工衛星の輪 3.19 より外）へ直した。

## 重要なレビュー箇所

1. **`EarthView.HideShellsWhereBlendingIsUnavailable`** — 回避策である。
   WebGLでの見え方をEditorと意図的に違えている。方針の可否は持ち主の判断による。
2. **同梱フォントのライセンス** — SIL OFL 1.1 での再配布と、改変名の扱い。
3. **`TimelinePlayback` の選べる速度** — ブラウザモック（`site/app.js`）は
   0.5/1/2 のままで、Unity側だけ 4/8 を足した。判定そのものは変えていない。
4. **`MoonView` の拠点の寸法** — 軌道半径3.5・大きさ1.0〜1.35は、
   翼の端が地球の表面（半径2.2）へ触れないことを前提にしている。どちらかを変えるなら両方見る必要がある。
5. **`orbitStation` の位置づけ** — 予測ではなく仮想シナリオの演出強度（0〜1）である。
   軌道高度・乗員数・電力を表さない。`parameterNote` にも追記した。
