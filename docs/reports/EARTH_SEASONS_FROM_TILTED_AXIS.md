# 地軸の傾きから季節を出す

対象：`unity/CivilizationToSpace/`
Unity：6000.4.8f1 / Built-in Render Pipeline

## 何を足したか

これまで太陽の向きは固定だった。`AppRoot.cs` のコメントも
「公転面・自転軸の傾き・季節は表していない。光の向きは固定である」と明記していた。
ここに季節を足す。

| # | 内容 |
| --- | --- |
| 1 | 地軸を23.4度傾ける。傾ける向きは視線の軸と直交させ、世界の中で変えない |
| 2 | 太陽の向きを、地軸に対して一年かけて上下に振る |
| 3 | 1年を時代1つぶん（1倍速で4秒）にする |
| 4 | 自転を1周45秒から1周1秒へ速める |

## なぜ地軸を傾ける必要があったか

**傾きが無いと、太陽を動かしても画面は何も変わらない。**

傾いていない球のまわりで光の向きを回すと、昼夜の境目は縦線のまま横へ流れる。
これは自転で起きることと同じで、見分けが付かない。

季節が季節に見えるのは、**傾いた軸が世界の中で向きを変えないまま、
太陽の向きだけが軸に対して上下する**ときである。このとき太陽の正面へ来る緯度が振れ、
昼夜の境目が斜めに倒れ、極が一日中明るい時期と一日中暗い時期が入れ替わる。

これまでの地球は傾いていなかった。`EarthView` は `Vector3.up` をそのまま
自転軸にしており、親の `Earth` も `Spin` も回転は単位だった。

## なぜ公転を一周させていないか

**一周させると、1年に一度、地球が真っ暗になる。**

太陽が地球のまわりを一周すると、固定したカメラから見た地球は月と同じように満ち欠けする。
太陽がカメラの側にあるときは全面が昼、地球の向こう側へ回ったときは全面が夜になる。
1年が4秒なので、**4秒ごとに地球が見えなくなる。**
時代ごとの地表を観察するための画面としては成り立たない。

実装前に3つの案を計算で比べた。

| 案 | 見えている円板のうち昼の割合 | 太陽の正面へ来る緯度 | 判定 |
| --- | --- | --- | --- |
| 太陽を公転面の上で一周させる | **0% 〜 100%** | ±23.4度（正しい） | 4秒ごとに真っ暗。地表が読めない |
| 視線を軸にした円錐の縁を一周させる | 78.7%で一定 | **-48度 〜 +62度** | 明るさは保つが、季節が±23.4度を超え、左右も揃わない |
| **採用：季節として現れる成分だけを振る** | **85.7%で一定** | **±23.4度（正しい）** | 両立する |

2番目の案は、この問題を先に見抜いていた別の実装からの引用である。
真っ暗を避けるという判断は正しかったが、季節の振れ幅が実際の2倍以上になり、
北と南で大きさも揃わない。採用しなかった。

## どう表しているか

太陽の向きを、互いに直交する3つの向きへの成分に分けて組み立てる。

| 成分 | 向き | 役割 |
| --- | --- | --- |
| 視線の軸 | `Vector3.back`（既定のカメラがいる側） | 昼の割合を決める。**年じゅう一定** |
| 地軸 | 北極の向き | 季節を決める。年で上下に振れる |
| 残り | 上の2つに直交する向き | 長さを1に保つぶん |

地軸を視線の軸と直交させてあるので、この2つの成分は互いに干渉しない。
**昼の割合を一定に保ったまま、太陽の正面へ来る緯度だけをちょうど±23.4度の範囲で振れる。**

地球は原点に置いたままで、動かしていない。カメラの寄り引き、月の周回、
形成過程の微惑星は座標を変えずに済んでいる。

太陽の振れる面は世界座標に固定してある。カメラを回り込ませれば夜側も見える。

## 値

| 項目 | 値 | 置き場所 |
| --- | --- | --- |
| 地軸の傾き | 23.4度（視線と直交、画面では左へ傾く） | `EarthView.AxialTiltDegrees` |
| 昼の割合 | 0.857（一定） | `AppRoot.LitFraction` |
| 1年 | 4秒 | `AppRoot.YearSeconds` |
| 自転 | 360度／秒（1周1.000秒） | `EarthView.SpinDegreesPerSecond` |
| 雲 | 372度／秒（地表との差12度／秒） | `EarthView.CloudDegreesPerSecond` |
| 太陽の強さ | 2.4（**時代によらず一定**） | `AppRoot.SunIntensity` |
| 環境光 | (0.040, 0.048, 0.066)（変更なし） | `AppRoot.SpaceAmbient` |

昼の割合を0.857にしたのは、**これまでと同じ明るさにするため**である。
以前の固定の光 Euler(28, -36, 0) を視線の軸へ射影すると0.714で、
昼の割合に直すと (1 + 0.714) / 2 = 0.857 にあたる。同じ値にしておけば、
季節が付いたこと以外は見え方が変わらない。

はじめ0.70で作ったが、実測したところ昼の見える割合が約80%から約53%まで落ちた。
下げるほど昼夜の境目が円板の内側へ寄って季節の傾きは読みやすくなる一方、
地表を見る面積が減る。**見え方で決めた値であり、太陽との距離や位置を表すものではない。**

## 1年を4秒にした理由と、そのために自転を速めた理由

1年を時代1つぶんにしたのは、**一つの時代を見ているあいだに季節がひと巡りする**
という見せ方を選んだためである。1時代は1倍速で4秒（`TimelinePlayback.BaseStepSeconds`）。

ここで自転を速める必要が出た。**1周45秒のままだと、1年のほうが1日より11倍短くなる。**
1年に365日が入っている地球とは逆さまで、1年のあいだに地球は32度しか回らない。
画面では季節ではなく、光が小刻みに揺れているように見える。

1周1秒にすると1年に4回まわる。日が過ぎて季節が移る、という順に読める。

再生の速度（0.5〜8倍）を変えても年の長さは変えていない。速度は段階の進み方を
変えるものであり、天体の動きまで速めると8倍速で自転が1周0.125秒になり、
地表が読めなくなる。

## 確かめたこと

### Unity の中で式を直に測った

`BehaviourCheck` の U-39・U-40 が、年を721点に刻んで毎回測る。

| 経過（秒） | 昼の割合 | 太陽の正面へ来る緯度 | 北半球 |
| --- | --- | --- | --- |
| 0.0 | 85.7% | 0.00度 | 春分 |
| 1.0 | 85.7% | +23.40度 | 夏至 |
| 2.0 | 85.7% | 0.00度 | 秋分 |
| 3.0 | 85.7% | -23.40度 | 冬至 |
| 4.0 | 85.7% | 0.00度 | 春分へ戻る |

地軸は `(-0.3971, 0.9178, 0.0000)`。世界の上向きから23.40度で、視線の軸との内積は0。
画面では地軸が寝ずに立ったまま傾いて見える。

### 実際に描いた絵を画素で測った

`CaptureTool` で1280x720へ書き出し、地球の円板の中を測った。
変更前（季節なし）と、今回（春分の姿）を並べる。

| 時代 | 変更前 平均 / 明るい割合 | 今回 平均 / 明るい割合 |
| --- | --- | --- |
| Hadean | 116.80 / 91.2% | 123.26 / 91.1% |
| EarlyOcean | 34.25 / 72.3% | 33.88 / 71.4% |
| Snowball | 36.53 / 79.2% | 35.55 / 75.9% |
| GreenEarth | 41.31 / 80.7% | 32.06 / 71.7% |
| Information | 37.80 / 79.7% | 35.05 / 80.3% |
| Future | 43.61 / 87.1% | 43.37 / 84.9% |

**明るさは変更前とほぼ同じに保てている。** 差が残る時代があるのは、
自転が1周1秒になったため、撮った瞬間に正面へ来ている大陸が変更前と違うからである。

### 画素では季節の南北を判定できない

円板の上半分と下半分の明るさを比べると、**季節が逆に出る**。
夜側の街の明かり、溶岩、大気のふちが混ざるうえ、地軸が傾いているため
画面の上下と緯度の南北が一致しないためである。
季節の向きと振れ幅は画素ではなく式から測る（U-39・U-40）。

## 時代による違いは入れていない

**太陽の明るさは全時代で一定にした。** 若い太陽が暗かったこと、昔の1日が短かったこと、
いずれも表していない。時代が進んでも光の当たり方は変わらない。

1年は時代1つぶんなので、どの時代でも同じように季節がひと巡りする。
「その時代の1年」ではなく、「時代を1つ見ているあいだに1年ぶんの光の動きを見る」
という表し方である。

## 副作用

自転を45倍にしたため、他の周回との関係が変わった。速さを変えていないのに
「1日あたり何周するか」が変わる。

| | 1周の秒数 | 変更前（1日45秒） | 変更後（1日1秒） | 実際 |
| --- | --- | --- | --- | --- |
| 月の周回 | 40秒 | 0.89日 | **40日** | 朔望月 29.5日 |
| 人工衛星 | 25.7秒 | 0.57日 | 25.7日 | 低軌道 0.06日 |

**月は実際に近づいた。** 朔望月29.5日に対して40日である。月の周回速度は変えていない。

**人工衛星は逆に遠ざかった。** 低軌道の衛星は1日におよそ16周するので、
本来は1日より短い周期でなければならない。ここでは25.7日かかっている。
速さを変えていないのは、変えると小さな点が輪になって尾を引き、
機体の数が読めなくなるためである。**見てから決めるべき点として残す。**

## 表していないこと

- 公転そのもの。太陽は一周せず、季節として現れる成分だけを往復する
- 公転面・離心率・近日点・遠日点。軌道の形は一切表していない
- 歳差・章動。地軸は世界の中で完全に固定してある
- 時代による違い。太陽の明るさも1日の長さも地軸の傾きも、全時代で同じ
- 太陽そのもの。画面に太陽は描いていない。あるのは光の向きだけである
- 実際の年数・日数・季節の長さ。秒数はすべて見え方で決めた値である
- 大気による薄明。昼夜の境目は地表の向きだけで決まる

## あわせて直したこと

シーン資産 `EarthTimelineDemo.unity` の平行光が、コードの値から取り残されていた。
資産側は Unity 既定のまま Euler(50, -30, 0)・強さ1.35で、`AppRoot` の
Euler(28, -36, 0)・強さ2.4と食い違っていた。実行時は `AppRoot.ApplySunLight` が
入れ直すので実害は無かったが、Playしていないときのプレビューだけ見え方が違っていた。
今回、資産を年の初めの向き（Euler(16.15, -41.99, 0)・強さ2.4）へ合わせた。

## 検証の道具に足したこと

`CaptureTool` に `-yearPhase` を足した。0で春分、0.25で夏至、0.75で冬至。

止めているあいだは年が進まないため、これが無いとどの1枚も年の初めの姿になる。
季節の端を撮って見比べるには、外から入れる必要がある。
`AppRoot.SetYearPhaseForTesting` がその入口で、`SetReducedMotionForTesting` と同じ扱いにしてある。

## 動作の点検に足した項目

`BehaviourCheck` の判定を16件から20件へ増やした（実行される判定の数）。

| 判定 | 内容 |
| --- | --- |
| U-37 | 動きを減らす前は太陽が季節で向きを変える |
| U-38 | 動きを減らすと季節も止まる |
| U-39 | 昼の割合は年を通して一定 |
| U-40 | 太陽の正面へ来る緯度が地軸の傾きぶん振れる |

U-30（動きを減らす前は自転している）の待ち方も変えた。これまでは0.5秒待って
回転差を測っていたが、自転が1周1秒になったため、1秒近く待つとちょうど一周して
差が0へ戻った瞬間を測ることがある。動いていても失敗と出るので、
角度が付くまで待ち、待てなかったときだけ失敗とする形へ改めた。
