# P0ブラウザモック実装報告：Earth Through Time

状態：実装済み・ブラウザ実機レビュー未実施。本書はB05（HTML/CSS/JavaScriptモック）の実装記録であり、B06（モックレビュー）の合格を意味しない。

## 実装目的

R1「Earth Through Time」のP0として、6時代の地球を観察・選択・再生できる最小のブラウザモックを、ローカルで起動・操作・レビューできる状態にする。計算モデルや3D品質ではなく、選択・再生・停止・比較の理解しやすさを検証することを目的とする。

対応するバックログ項目はB05、WBSはW4、要件はFR-01〜FR-05である。FR-06（Unity再現）はR1のP1であり本作業の対象外。

## 職場PC由来の既存2ファイルを引き継いだこと

本作業の開始時点で、`site/index.html` と `site/styles.css` が未追跡ファイルとして作業ツリーに存在していた。これは職場PCのローカルCodexで途中まで作成されたP0成果物であり、その会話履歴は本作業環境に存在しない。

## 実装した機能

### データと状態

- 時代データの正本は `site/data/earth-eras.json` のみ。`app.js` は時代の名称・年代ラベル・解説・イベント・視覚値を一切保持しない。`NEUTRAL_VISUAL`（欠損時の中立の地球）と `CSS_VARS`（CSS変数への対応表）はレンダリング側の都合であり、特定の時代を表すデータではない。
- 現在の時代索引、再生中か、速度、データ検証状態を単一の `state` オブジェクトで管理し、表示はすべてそこから導く。DOMごとに別の時代状態を持たない。
- 時代選択ボタン6個はJSONから動的に生成する。

### 操作

| 操作 | 実装 |
|---|---|
| 起動 | Hadean・停止・1x。自動再生しない。ブラウザがフォーム値を復元しても明示的に初期値へ戻す |
| 時代選択ボタン | 指定時代へ移動し、自動再生を停止 |
| 前／次 | 1時代移動し、自動再生を停止。Hadeanの前とFutureの次はボタンを無効化。循環しない |
| スライダー | 0〜5の整数、刻み1。範囲外値は丸める。操作で自動再生を停止 |
| 再生／停止 | 1x=4秒、0.5x=8秒、2x=2秒で次の時代へ。Future到達で自動停止 |
| Futureで再生 | Hadeanへ戻してから再生。停止中のFutureではボタン表記が「最初から再生」になる |
| 速度変更 | 再生状態を保ち、変更時点から新しい間隔で計時し直す。時代は変わらない |
| タブ非表示 | 自動再生を停止。再表示しても自動再開しない |
| タイマー | 常に最大1つ。予約前に必ず解除するため多重起動しない |

### 情報表示

時代変更のたびに、ID・時代名・年代ラベル・概要・視覚表現タグ・代表イベント・データ品質状態をまとめて同期する。色だけに依存せず、すべてテキストでも判別できる。

Futureでは「固定された予測ではなく、条件の異なる複数の未来を比較するための入口である」旨を明示し、読み取り専用の候補として「協働と保全」「資源制約への適応」を仮定の説明つきで表示する。選択・分岐のロジックは実装していない。

### エラー・データ欠損

| 状況 | 挙動 |
|---|---|
| ファイル取得失敗（`file://` で開いた場合を含む） | エラー表示。ローカルHTTPサーバー経由で開くよう案内し、操作を無効化 |
| HTTPエラー、JSON構文不正、未対応の`schemaVersion` | それぞれ固有のエラー文を表示し、操作を無効化 |
| 時代が6件でない、ID重複、sortOrder重複・非連番、`eraOrder`不一致 | 全体エラーとして操作を無効化 |
| 必須文字列（id／displayName／rangeLabel／summary／status）の欠損 | 全体エラー |
| `visual` または `presentation` コンテナ自体の欠損 | 全体エラー |
| `visual` の個別パラメータ欠損・型不正・範囲外 | **全体エラーにせず**中立の地球へ置換し、「簡略化して表示している」旨の注記を表示 |
| 色指定がCSSとして無効（`#12345` などの5桁・7桁を含む） | 同上。中立色へ置換して注記を表示 |
| `events` や `tags` が空 | 該当セクションを非表示にするだけ |
| 再読み込みボタン | データを再取得し、成功すれば操作を再有効化して初期状態から再開 |

利用者へ表示する文言は事前に定義した日本語メッセージのみで、内部パス・例外全文・スタックトレースは表示しない。

### 堅牢性

すべてのイベントハンドラとタイマーコールバックを共通の `guard()` でラップし、`window` の `error` / `unhandledrejection` も捕捉する。想定外の例外が起きても画面全体が無反応にならず、案内文を表示して安全な状態で停止する。

`innerHTML` は一切使用せず、JSON由来の文字列はすべて `textContent` で挿入する。`localStorage` の使用、外部送信、個人情報の取得はない（NFR-05）。

## ローカル起動方法

外部ライブラリ・CDN・npm・Node.js・フレームワーク・外部APIは使用していない。ブラウザとローカルHTTPサーバーだけで起動する。

1. 下記のいずれかの方法でローカルHTTPサーバーを起動する
2. ブラウザ（Chrome または Edge を初期検証候補とする）で `http://localhost:8080/` を開く
3. 停止はサーバーを起動したコンソールで `Ctrl+C`

`index.html` をエクスプローラーからダブルクリックして `file://` で直接開くと、ブラウザのセキュリティ制約により `fetch` が失敗し、時代データを読み込めない。この場合も画面は白紙にはならず、「ローカルHTTPサーバー経由で開いているか確認してください」というエラーが表示され、操作は無効化される。

## PowerShellでのローカルHTTPサーバー起動例

追加インストール不要で、Windows標準の `System.Net.HttpListener` だけで動作する。管理者権限は不要。

次の内容を `serve.ps1` として**プロジェクトフォルダの外**（例：デスクトップや一時フォルダ）に保存し、PowerShellから `.\serve.ps1` で実行する。

```powershell
Set-Location C:\Users\Tan0Ry0\Desktop\26dev\civilization-to-space\site
$root = (Get-Location).Path
$listener = New-Object System.Net.HttpListener
$listener.Prefixes.Add('http://localhost:8080/')
$listener.Start()
Write-Host 'Serving http://localhost:8080/  (Ctrl+C to stop)'
$types = @{ '.html' = 'text/html; charset=utf-8'; '.css' = 'text/css; charset=utf-8'; '.js' = 'text/javascript; charset=utf-8'; '.json' = 'application/json; charset=utf-8' }
try {
    while ($listener.IsListening) {
        $ctx = $listener.GetContext()
        $rel = [System.Uri]::UnescapeDataString($ctx.Request.Url.AbsolutePath).TrimStart('/')
        if ($rel -eq '') { $rel = 'index.html' }
        $full = [System.IO.Path]::GetFullPath((Join-Path $root $rel))
        if ($full.StartsWith($root, [System.StringComparison]::OrdinalIgnoreCase) -and (Test-Path $full -PathType Leaf)) {
            $bytes = [System.IO.File]::ReadAllBytes($full)
            $ext = [System.IO.Path]::GetExtension($full).ToLower()
            if ($types.ContainsKey($ext)) { $ctx.Response.ContentType = $types[$ext] }
            $ctx.Response.OutputStream.Write($bytes, 0, $bytes.Length)
        }
        else { $ctx.Response.StatusCode = 404 }
        $ctx.Response.Close()
    }
}
finally { $listener.Stop() }
```

このスクリプトは本作業中に実際に実行し、`/`（index.html）・`/styles.css`・`/app.js`・`/data/earth-eras.json` がいずれもHTTP 200で、実ファイルとバイト一致で配信されること、存在しないパスが404を返すことを確認済み。

**注意事項**

- スクリプト内に日本語を書かずASCIIのみにしてある。Windows PowerShell 5.1 はBOMなしUTF-8の `.ps1` を既定コードページとして読むため、日本語文字列を含めると構文エラーになる（本作業中に実際に発生した）。日本語メッセージを入れたい場合はUTF-8（BOM付き）で保存すること。
- 8080番が使用中の場合はポート番号を変更する。
- プロジェクトフォルダ内には保存しない。今回のコミット対象は指定5ファイルのみであり、この補助スクリプトは成果物ではない。
- Pythonが導入済みの環境であれば `python -m http.server 8080` を `site` フォルダで実行しても同じことができる。ただしPythonの導入自体は本プロジェクトの依存に含めない。

## 科学的・表現上の注意

- 本モックは**科学的な将来予測でも精密な地球科学モデルでもない**。地球の長い変化を象徴的に体験・考察するための初期プロトタイプである。この旨は画面上部の免責文として常時表示している。
- 6時代は地質年代の厳密な区分ではない。年代ラベルは数値年代を示さない説明用ラベルであり、科学的な区分名・期間・分布を保証しない。数値年代の追加には出典確認とレビューを要する。
- `visual` の数値は**0〜1に正規化した象徴表現の演出強度**であり、気温・海水量・森林面積・人口などの観測値や予測値ではない。`satelliteCount` は表示する衛星の個数を示す象徴的な整数である。この旨はJSONの `parameterNote` に記載し、地球の下の注記として画面にも表示している。
- 赤は熱、青は海、白は氷、緑は陸上生態系、光点と線は接続を示す視覚的な比喩である。地図・境界・実際の分布・同時性を表すものではない。
- Futureの2案は**仮定に基づく探索用**であり、発生確率、実現年、優劣、投資・政策判断の根拠を提供しない。「協働と保全」は成果を保証せず、「資源制約への適応」は失敗の結末を意味しない。データ品質状態を「仮想シナリオ案」と表示し、他5時代の「象徴表現案・出典未検証」と区別している。
- 単線的な進歩史、文明の優劣順位、必ず宇宙へ進む結末は表現していない。人類・文明はInformationへの導入として扱い、第7の時代を追加していない。

## ロールバック方法

本コミットは5ファイルすべてが新規追加であり、既存の追跡ファイルを一切変更していない。したがって取り消しは他へ影響しない。

**push後に取り消す場合（推奨）**

```powershell
git revert <このコミットのハッシュ>
git push origin main
```

履歴を書き換えずに打ち消しコミットを作る。`--force` は不要。

**push前にローカルだけ取り消す場合**

```powershell
git reset --soft HEAD~1
```

ステージングされた5ファイルは作業ツリーに残るため、内容を失わない。

`site/` と `docs/reports/P0_BROWSER_MOCK_IMPLEMENTATION.md` を削除すればよい。既存の文書・設定・GitHub Pagesの構成は本作業で一切変更していないため、削除しても他の機能は影響を受けない。

1. **実ブラウザでのレビュー（B06／W5）**。Chrome／Edgeで M-01〜M-20 を実施し、検証版・端末・結果を記録する。特に6時代の地球が見分けられるか、360pxと200%拡大で崩れないかを確認する。ここで初めてAC-06とAC-08を合格と判断できる。
2. **Futureシナリオ選択の実装（FR-04／AC-05）**。「協働と保全」「資源制約への適応」の切替UIを追加し、時代IDをFutureに保ったまま案名・説明・視覚表現だけを切り替える。案は時代と別のIDを持たせ、選択をセッション内で保持する。仕様書の「起動時はCooperation」も併せて実装する。
3. **端でのフォーカス喪失対策**。前後ボタンが無効化されたときにフォーカスが失われないよう、無効化ではなく `aria-disabled` と操作の無視に切り替えるか、フォーカスを隣接要素へ移す方式を検討する。実機確認の結果を踏まえて判断する。
4. **地球表現の調整**。実機確認の結果に応じて、`ice` レイヤの覆い方や `land` と `--ocean` の連動など、既存CSSの見直しを承認のうえ行う。
5. **Unity移行データ形式の確定（W6の前提）**。本実装のキー名と仕様書の項目案のどちらを共通交換形式にするかを決め、`schemaVersion` の運用方針とともに文書化する。
6. **年代ラベルの出典確認**。数値年代を表示するかどうかを含め、出典とレビュー体制を決める。現状は数値年代を一切表示していない。
7. **レビュー結果の記録先**。`docs/reports/` にモックレビュー報告を追加する（B06の完了条件）。
