# 形成過程を重力の計算で動かす（実装報告）

| 項目 | 内容 |
|---|---|
| 対象 | 微惑星の集積 → 原始地球 → ジャイアントインパクト → 月の分離 |
| 追加 | ブラウザ版 `site/formation.html` と、Unityの `FormationSim` シーン（`SimRoot`） |
| 検証の正 | 計算部分の単体実行（C#はMono、JavaScriptはNode.js）と、canvasの呼び出しを記録する代用DOM上での通し実行。**Unityでの実行・実ブラウザでの表示は未検証** |

## 既にあるものとの違い

| | 何を出すか | 位置の決め方 | 次元 |
|---|---|---|---|
| `FormationView`（既存・Unity） | 形成過程の4段階 | 手で書いた0〜1の演出値を `Mathf.Lerp` で補間 | 3D |
| `site/gravity-sim.html`（既存） | 重力と合体そのもの。原始天体ができるまで | 引力の計算 | 2D |
| **本実装**（追加） | **月が分かれるところまで通す** | 引力の計算 | 3D |

既存の2つは消していない。`gravity-sim.html` は「重力と合体を条件を変えて触る箱庭」、
本実装は「地球ができるまでを最後まで通す」ものとして、互いにリンクを張った。

`FormationView` を残しているのは、`earth-formation.json` の `parameterNote` が
「象徴表現の演出強度であり、質量・個数・速度・衝突エネルギーの見積もりではない」と
定めているとおり、**あれは条件を変えても結果が変わらない**ためである。
見せたいものが違うので、置き換えずに並べている。

## 何を計算しているか

- 天体どうしの万有引力を毎ステップ総当たりで足し、速度と位置を更新する
- 半径の和より近づいた対を、質量と運動量を保って合体させる
- 段階は時間で切り替えない。**計算された状態**から遷移する
  （例：いちばん重い塊が全体の78%を超えたら「原始地球」）
- 乱数は種を決めれば同じ結果になる（`UnityEngine.Random` は共有状態を持つので使わない）

## 何を計算していないか

**1. 衝突で破片が飛び散る過程**

物質の流体としての振る舞いを解いていない。衝突の瞬間に「決めた質量の破片を、
決めた範囲へ置く」という手続きに置き換えている。衝突から取っているのは**円盤の向きだけ**で、
当て方を変えると円盤の向きが変わる。それ以外の量は設定値である。

**2. 破片どうしの引力を強めている**

破片は軽く、地球のそばでは潮汐に負けて集まれない。実際の月も、円盤が集まるまでに
何十回も回っている。その回数ぶんの時間を縮めるかわりに、破片どうしのあいだだけ
引力を既定で60倍にしている。**物理としては正しくない。**
画面の「条件を変える」に出してあり、1倍に戻すと月にならないことを確かめられる。

**3. 抵抗を2種類入れている**

集積中のガス抵抗と、衝突後の円盤の粘り（軌道を円くする向きにだけ効かせる）。
どちらも「見ていられる速さ」に合わせた値で、密度や粘性率から求めた量ではない。

**4. 単位がない**

地球の最終質量を1とした相対値である。**実際の質量・距離・年数ではない。**
読み取れるのは順序と、条件と結果の関係だけである。

## 測ったこと

計算部分だけを取り出して実行した。Unityやブラウザでの実行ではない。

**種を12通り変えて、C#版・JavaScript版とも12回すべて「地球と月の2つ」で終わった。**
両者は決着時刻・天体数・月と地球の質量比・距離まで一致する
（乱数がxorshift32で一致し、値を32ビット浮動小数に置いているため）。

| 段階 | 到達時刻（計算上の時間） |
|---|---|
| 原始地球 | t = 15〜17 |
| 衝突 | t = 24〜26 |
| 決着（地球と月） | t = 28〜30 |

月と地球の質量比は0.0006〜0.0225に散った。密度を一定とみなす本実装では、
質量比0.022は半径比0.28にあたり、実際の月の半径比0.273に近い見え方になる。
**質量比そのものは実際の0.0123と違う。**

### 速さ

| 微惑星の数 | 1ステップ | 1フレーム（3ステップ） |
|---|---|---|
| 200 | 0.28ms | 0.85ms |
| 380（既定） | 0.92ms | 2.76ms |
| 520 | 1.67ms | 5.00ms |
| 700 | 3.20ms | 9.61ms |

Intel Xeon 2.10GHz・Mono での値である。**実機の値ではない。**
総当たりなので個数の2乗で効く。合体が進むと軽くなる。

### 途中で見つけて直した4つ

読むだけでは見つからなかった。どれも実行して測って分かったものである。

| 何が起きたか | 原因 | 直し方 |
|---|---|---|
| 集積が終わらない（天体3〜4個のまま t=340 まで進んでも63%） | 残った数個が安定な組になり合体しない | 集積中だけ抵抗を入れた |
| 破片が月にならない（十数個のまま散らばる） | 破片が軽く、地球の潮汐に負ける | 破片どうしの引力を強めた |
| 月が小さすぎ・地球に近すぎ（質量比0.0002、距離1.2R） | 粘りを「平均速度へ引き寄せる」形にしたら周回そのものが消えた | 「軌道を円くする」向きに変えた |
| **できあがった月が画面に映らない**（「天体2個」と出ているのに描いているのは1個） | カメラの寄せ先を質量の94%が入る範囲で決めていた。地球が全体の98%を占めた時点で地球へ寄りきる | 重い上位2つを必ず入れるようにした。終盤は地球と月、衝突前は地球と衝突天体にあたる |

## 公開中のビルドへ影響させないための決め

- **`FormationSim` シーンはビルド設定の末尾に足す。先頭に入れない。**
  先頭のシーンが起動時に開くため、先頭へ入れると公開中のWebGL（`EarthTimelineDemo`）が
  入れ替わってしまう
- 材質は `Shader.Find` で組まず、`StandardMaterials` の雛形を複製する。
  実行時にしか組まない組み合わせはビルドで削られ、WebGLでは正しく描かれない
  （`StandardMaterials` の説明にある問題と同じ）
- まとめ描きに対応していない環境では1個ずつ描くように落とす
- `site/formation.css` のセレクタは `#formation-` と `#view-switch` の配下に限定し、
  `styles.css` は変更していない
