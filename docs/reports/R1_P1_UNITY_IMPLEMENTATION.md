## 自前のJSONリーダーを書いた理由

Unity標準の `JsonUtility` は、キーが存在しないことと値が `0` であることを区別できない。[データ交換形式](../design/DATA_INTERCHANGE_R1.md) は「`visual` の個別キーの欠損・型不正・範囲外は中立値へ置換して注記を出す」と定めており、`JsonUtility` ではこの規則を満たせない。

外部パッケージを増やさず規則を満たすため、`Assets/Scripts/Core/Json/` に最小のリーダーを書いた。RFC 8259 に従い、末尾カンマ・コメント・単一引用符・NaN・Infinity を受け付けない。入れ子は64段で打ち切る。重複キーは後勝ちとし、ブラウザの `JSON.parse` と同じ結果にしている。

この判断の正しさは、検証の #17（値が `null`）と #18（値が `0`）で示している。前者は縮退し、後者は縮退しない。

## データの同一性

正本は `site/data/earth-eras.json` のみである。Unityは `Assets/StreamingAssets/earth-eras.json` だけを読む。更新の向きは一方向で、Unity側から正本へ書き戻さない。

```text
git rev-parse HEAD:site/data/earth-eras.json
  → 6bfda2441b7827e3a310209822859c6025c819da
git rev-parse HEAD:unity/CivilizationToSpace/Assets/StreamingAssets/earth-eras.json
  → 6bfda2441b7827e3a310209822859c6025c819da
```

blobハッシュが一致する。`Tools/Civilization to Space/交換データのコピーを照合` でいつでも再確認できる。

照合はLF正規化後の内容で行う。`core.autocrlf` が有効な環境では、正本は作業ツリー上でCRLF、コピーは `unity/.gitattributes` の `eol=lf` によりLFになるため、生バイトの比較は環境によって食い違う。データ交換形式が「blobハッシュを正とする」と定めているのに合わせた。

## 地表の表現

一様な色の球では、自転していても動いて見えず、時代ごとの違いも色の差でしか読めない。オーナーの指摘を受けて、地表を時代ごとに手続き的に描く方式へ変えた。

| 要素 | 対応する値 | 描き方 |
|---|---|---|
| 海と陸 | `oceanLevel` | 陸の強さを面積の割合で切り分ける。海0.9で陸およそ3割 |
| 大陸の配置 | 時代の位置 | 時代ごとに定義した陸塊。小さな陸塊→ひとつの超大陸→分かれた複数の大陸 |
| 起伏 | 高さ | メッシュを半径の4.5%まで膨らませ、法線マップで陰影も付ける。海面は平ら |
| 植生 | `vegetation` | 低緯度・低地の陸ほど濃い緑。斑を作り一様な塗りにしない |
| 氷 | `iceCoverage` | 極から緯度を下げて覆う。境目はノイズでぼかす |
| 火山 | `volcanicActivity` | 割れ目として光らせる。面全体を光らせると飽和して地形が消える |
| 都市光 | `cityLights` | 陸の低地に点として散らす |
| 雲 | `cloudDensity` | 別の層。地表より速く流す |

画像素材も外部の地図データも使わない。すべて `visual` の値と自前の3次元ノイズから作るため、容量もライセンスの問題も生じない。時代ごとに1度だけ焼き、1フレームに1時代ずつ先に用意するので、再生中に画面が止まらない。

海陸の境は、ノイズのしきい値ではなく**面積の割合**で決めている。ノイズの値の分布は一様ではなく、しきい値を直に決めると海の広さが意図と大きくずれるためである。

### 大陸の配置について

**これは古地理の再現ではない。** 時代データの品質状態はすべて「象徴表現案・出典未検証」であり、注意書きも「年代・分布・順序の厳密さを保証しません」と明記している。`PlanetGeography` が持つのは、地球の長い変化を読み取りやすくするためにデフォルメした象徴的な配置であり、特定の年代の大陸の位置・形・面積を主張しない。

意図しているのは「陸が集まり、また分かれた」という変化が絵として読めることだけである。

| 段階 | 配置 |
|---|---|
| マグマの地球 | 陸塊を置かない。海が無いため全面が陸になる |
| 海の誕生・全球凍結 | 小さな陸塊が4つ |
| 森林と陸上生態系 | ひとつの大きな陸 |
| 情報・地球規模接続・未来の分岐 | 分かれた複数の大陸 |

出典に基づく古地理を描くには、いま持っていない海岸線データが必要になる。

### 起伏について

実際の地球の起伏は半径の0.1%ほどで、そのままでは見えない。読み取れるようにデフォルメし、半径の4.5%まで誇張している。

- メッシュは経度192・緯度96に分割した自前の球で、高さに応じて半径を動かす
- 法線マップで陰影にも起伏を出す。これが無いと色は変わっても面が平らに見える
- **海面は平ら**にする。見えているのは水面であって海底ではない。海底を凹凸にすると水面が波打ち、輪郭も陰影も硬くなる
- 時代が変わるときは頂点の高さも補間する。大陸がせり上がり、また沈む様子がそのまま動きになる

## 地球ができるまで（段階F）

オーナーの要望により、6時代の手前に形成過程を足した。

### これが何であって、何でないか

**仮説に基づく象徴表現である。** 月の成り立ちについてはジャイアントインパクト説を採っているが、**決着した事実ではない**。データ品質状態は全段階「仮説に基づく象徴表現案・出典未検証」であり、年代・順序・規模・回数の厳密さを保証せず、出典も検証していない。

質量・個数・速度・衝突エネルギー・衝突角度を一切持たない。大きさも速さも、画面で読み取れることだけを基準に決めた値である。

段階の名称にも「（仮説）」を付け、説明の年代ラベルの位置に「地球ができるまで（仮説に基づく象徴表現）」と常に出している。

### 段階

| 段階 | 内容 |
|---|---|
| 微惑星の集積 | 小さな天体が数多くぶつかり、塊が育つ |
| 原始地球 | ぶつかる天体が減り、熱を持った大きな塊になる |
| 巨大衝突（仮説） | 大きな天体が近づく。ぶつかる瞬間は描かない |
| 月の形成（仮説） | 破片から月ができたとする仮説 |

### 実装

| 要素 | 対応する値 | 描き方 |
|---|---|---|
| 塊の大きさ | `bodyScale` | 地球そのものを小さくする。段階が進むと大きくなる |
| ぶつかる天体 | `swarm` | 外から中心へ落ち、届いたら外から出し直す |
| 大きな天体 | `impactor` | 斜めから近づく。衝突の瞬間は描かない |
| 破片 | `debris` | 地球のまわりの輪。等間隔にせず散らす |
| 月 | `moon` | 月の形成で現れ、以後は消さない |

月は形成過程で現れたあと消えない。時代のあいだはカメラが地球へ寄るため、画面の外にある。

## 月への展開（段階M）

[R1-P1以降の実装順序](../planning/IMPLEMENTATION_ORDER_AFTER_R1_P1.md) の段階Mを実施した。

### これが何であって、何でないか

**予測でも計画でもない。** 仮想シナリオのひとつを象徴的に表す演出である。データ品質状態は全段階「仮想シナリオ案」であり、実現の可否・時期・確率を示さない。「テラフォーム」「移住が実現する」といった断定する語を画面へ出していない。

実際の軌道要素・距離・周期・推進・生命維持・資源収支を**一切持たない**。月の半径・距離・周回の速さは、画面に収まり読み取れることだけを基準に決めた値であり、実際の比ではない。

[ロードマップ](../planning/ROADMAP.md) は月の居住をR6に置いている。段階MはR6の実装ではなく、そこへの先回りである。R6が求める資源収支のモデルは持たない。

### 段階

| 段階 | 内容 |
|---|---|
| 到達 | 行き来が始まっただけ。月面に拠点なし |
| 補給拠点 | 運び込みに支えられた拠点。地球への依存が高い |
| 資源利用 | 現地のものを使い始め、拠点が広がる |
| 居住 | 拠点が連なる。地球化ではない |

### 実装

| 要素 | 対応する値 | 描き方 |
|---|---|---|
| 行き来 | `transfer` | 地球と月のあいだを弧を描いて往復する物体。数と速さが変わる |
| 月面の拠点 | `facility` | 月面の一帯に置いた小さな箱。段階が進むと増える |
| 月面の明かり | `surfaceLights` | 拠点の発光 |

月面も地球と同じく手続き的に描く。灰色の地に暗い海とクレーターの明暗を置く。画像素材を持ち込まない。

### 時系列への組み込み

**オーナー判断により、再生するとFutureの先へ続けて進む。** 時代データは増やしていない。`EraTimeline` に「時代の手前と先に続く段階」を持たせ、形成過程の4段階を手前へ、月の4段階を先へ置いた。したがって `EraCount` は6のままで、時系列全体は14段階になる。

月の段階に入るとカメラが引き、地球と月の両方が画面へ入る。引く量は倍率ではなく「収めたい半径」で決める。倍率で決めると画面の大きさによって収まり方が変わるためである。

操作帯では月の段階のボタンを紫系にし、時代と同じものに見せないようにしている。

## 時代ごとの見分けやすさ

[R1-P0レビュー報告](R1_P0_HUMAN_REVIEW.md) は、InformationとFutureが見分けにくいことを既知の制約として受容したうえで、「Unityの発光表現はブラウザと異なるため、Unity上で改めて見え方を確認し、その結果を実装報告に記録する」としていた。本節がその記録である。

同じ手法（地球の描画領域のみを切り出した15ペアの画素差）で測った。

| 段階 | 最も近いペア | 平均差 |
|---|---|---|
| ブラウザ | Information と Future | 3.56 |
| Unity（一様な色の球） | Information と Future | 6.82 |
| Unity（地表を描く） | EarlyOcean と Information | 13.73 |
| Unity（大陸配置と起伏） | **Information と Future** | **21.71** |

最も近いペアの差は、ブラウザの3.56から**21.71へ6倍に開いた**。InformationとFutureは再び最も近いペアだが、その差は当初の6倍あり、見分けられる。

[6時代カタログ](../design/EARTH_ERA_CATALOG.md) がFutureを「同じ地球に異なる光・緑・接続」と定義しているため、両者の大陸配置は同一にしてある。違いは植生と都市光の量だけである。見分けやすくするために `visual` の値を動かすことはしていない。

## ブラウザ仕様からの逸脱

[R1-P1実装順序](../planning/IMPLEMENTATION_ORDER_R1_P1.md) に記録済みの逸脱2・3を実装した。加えて、実装の過程で生じた判断を以下に記す。

### 記録済みの逸脱

| # | 内容 | 実装 |
|---|---|---|
| 逸脱2 | 地球をゆっくり自転させる | **毎秒8度**。地球の親を回し、カメラは回さない |
| 逸脱3 | マウスでカメラを回転・ズームできる | ドラッグで回転、ホイールで寄る。仰角±70度、寄り0.55〜2.4倍で端止め |

動きを減らす代替手段として、画面に「動きを減らす」トグルを常設した。オンにすると自転・衛星の周回・時代遷移の補間が止まる。`PlayerPrefs` を使わず、セッション内のメモリにのみ保持する。

3D操作は発見可能性が低いため、操作方法を画面に表示している。ただし文字を減らすため、「説明を出す」を押したときだけ出る。

### 本実装で生じた判断

| # | 内容 | 理由 |
|---|---|---|
| 1 | スライダーはS3ではなくS4で追加 | 時系列の制御であり、再生と一緒に作るほうが筋が通る |
| 2 | 利用者向け文言を1箇所だけ変更 | 「この**モック**が対応していないデータ形式です」→「この**実装**が…」。判定条件は同一 |
| 3 | 右の説明パネルの幅を画面比で決める | 固定幅では狭い画面で画面外へ出る。カメラのフレーミングも同じ値を参照する |
| 4 | 地球の層を混色＋加算合成にする | 均一な半透明の殻を重ねると外側が内側を覆い、値の違いが読めなくなる |
| 5 | Playしていなくてもシーンビューに地球を出す | `DontSave` を付けており、`.unity` には保存されない |
| 6 | `presentation.storyboardCut` を読み込まない | 絵コンテのカット番号を画面へ露出させないため |
| 7 | 自転を毎秒3度から**8度**へ | 3度では動いていることが読み取りにくいというオーナーの指摘による。実装順序は「毎秒3度程度」としており、本項はそこからの変更である |
| 8 | 説明の表示を**既定で隠す** | 地球を大きく見せるためのオーナーの指示。操作帯の「説明を出す」で切り替えられる |
| 9 | 地表を手続き的に描く | 一様な色の球では動きも時代差も読み取れないため（前掲） |
| 10 | 大陸を時代ごとに配置し、起伏を誇張する | 「史実に近い形でデフォルメして分かりやすく」というオーナーの指示による。古地理の再現ではない旨をコードと本書に明記した |
| 11 | 月への展開を、再生でFutureの先へ進む形で足す | オーナーの指示による。ロードマップのR6への先回りであり、[R1-P1以降の実装順序](../planning/IMPLEMENTATION_ORDER_AFTER_R1_P1.md) に記録した |
| 12 | 地球ができるまでを、6時代の手前に足す | オーナーの指示による。時代データは増やさず、時系列の手前の段階として持つ |

判断4は、最初の実装が失敗したことによる修正である。均一な殻を重ねた版ではInformationが白一色になり、海も植生も読めなかった。

## R2-P1への境界

R1側が公開するのは、`AppRoot.Playback` を通じた `IsPlaying`（再生中かを読む）と `RequestStop`（停止を要求する）の2つだけである。`TimelinePlayback` はこれ以外をR2-P1へ向けて公開しない。`static` も `Singleton` も作っていない。

語彙も分離した。`Scenario` はFutureの2案にのみ使い、`Condition` はR2-P1のために空けてある。

## 起動手順

1. Unity Hub で `unity/CivilizationToSpace/` を 2022.3.11f1 で開く
2. `Assets/Scenes/EarthTimelineDemo.unity` を開く
3. Play を押す

Playしなくても、シーンビューには地球が表示される。`AppRoot` の Inspector にある `Preview Era Index` を 0〜5 に変えると、表示する時代が変わる。

Game ビューは `Scale` を `1x` にして使う。`Scale` は表示倍率であり、1より大きいと画面が切れる。

## 未実施の検証

以下は実施していない。**未実施であり、成功とは判断していない。**

- **人が読んだときの受け取り方**。UAC-15。必要な文言が画面上に存在することは確認したが、読んだ人が意図どおり理解するかは確かめていない。これは人でなければ確認できない
- **オーナー自身によるPlay Modeでの操作**。ドラッグ・ホイール・ボタンの押し心地は、実際に操作しなければ分からない
- **スタンドアロンビルド**。[R1-P1実装順序](../planning/IMPLEMENTATION_ORDER_R1_P1.md) のUG-11は本書の対象外としている
- **ブラウザとの機械的な突き合わせ**。22の異常系をapp.js側へ同じ順で流していない。判定の一致は、app.jsのソースに対して1対1で書いたことによる担保である
- **スクリーンリーダーでの読み上げ**。uGUIは支援技術に対応しない（下記の制限）
- **Windows以外の環境**。日本語フォントの解決はWindowsのフォント名に依存する

## 既知の制限

- **スクリーンリーダーに対応しない**。UnityのuGUIは支援技術へ情報を渡さない。ブラウザ側がARIAで実現していることを、Unity側では実現できない。実現不能として記録する
- **日本語フォントはOSに依存する**。`Yu Gothic UI` などWindowsの標準フォントを優先順で探す。見つからない環境では内蔵フォントへ落ち、日本語が出ない可能性がある
- **InformationとFutureは地球の見た目だけでは区別しにくい**（前掲）。設計意図であり、区別はテキストが担う
- **FR-04／AC-05（Futureの2案切替）は未実装**。将来シナリオ候補は読み取り専用の表示に留まる。ブラウザ側も未実装であり、両実装の対称性を保つために意図的に繰り延べている
- **ブラウザとUnityで見た目は一致しない**。[ブラウザモック仕様](../design/BROWSER_MOCK_SPEC.md) が「両実装の見た目の完全一致は求めない」と定めている
- **Game ビューの `Scale` は利用者の設定**。1より大きいと画面が切れる。実装側からは制御できない
- **説明は既定で表示しない**。地球を大きく見せるためであり、[体験ビジョン](../design/PRODUCT_VISION_R1.md) の「色だけで意味を伝えず、名称と説明を併記する」とは食い違う。操作帯の「説明を出す」で表示できるが、既定の状態ではこの原則を満たしていない
- **大陸の配置は実際の大陸移動ではない**。時代ごとに位置と形が変わることを示す象徴表現であり、古地理の再現ではない
- **月への展開は予測でも計画でもない**。仮想シナリオであり、実現の可否・時期・確率を示さない。軌道・距離・周期・資源収支のモデルを持たない
- **月の段階は時代ではない**。時代データは6件のままで、`EraTimeline` の先に続く段階として持っている
- **形成過程は仮説である**。ジャイアントインパクト説は月の成り立ちの有力な説だが、決着した事実ではない。衝突の規模・角度・時期・回数を示さない
- **形成過程の段階も時代ではない**。`EraTimeline` の手前の段階として持っており、時代データは6件のままである
