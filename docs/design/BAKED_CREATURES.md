# 距離関数で獣を作り、網目に焼いて地表へ置く（手順書）

状態：**手順は確立。Unity での表示も確認済み**（2026年9月21日）
対象：[試作](../prototypes/mammoth.html)、[焼くスクリプト](../prototypes/bake_creatures.py)、
`unity/CivilizationToSpace/Assets/Scripts/View/SurfaceView.cs`

## なぜこの手順があるか

地表の生きものは球と円柱の組み立てで、**毛皮が作れなかった。**
毛の分だけ表面を外へ押し出す方法がないためである。短い骨を輪に並べて裾にした試みは、
1本ずつが瘤に見えて輪郭が寸胴になり、見送られた（`BuildTusker` の注）。

距離関数（点から表面までの距離を返す式）なら、表面を揺らぎの分だけ外へ押し出せる。
そこで**ブラウザで形を決め、同じ式を網目に焼いて、Unity へは素材ファイルとして置く。**
Unity 側は外から持ってきた素材と同じ読み込みに乗るので、場面専用の処理は増えない。

## 1. ブラウザで形を決める

**座標は「前 = +x、上 = +y、横 = ±z」、単位はメートル相当。** 足の裏が y=0。

形は4つの部品だけで組む。

| 部品 | 使いどころ |
| --- | --- |
| `sdEll`（楕円体） | 胴・こぶ・頭・耳 |
| `sdCap`（太さの変わる筒） | 脚・鼻・尾・牙・角 |
| `smin`（なめらかにつなぐ） | 部品どうしの継ぎ目を消す。k が大きいほど太くつながる |
| `q = (x, y, |z|)` | 左右対の部品（耳・牙）を1回書くだけで両側に出す |

**四つ足の型。** 脚は `leg(腰, 足先, 位相, 歩幅, 持ち上げ, 太さ3つ)`、
毛皮は `furD(垂れる帯の上端, 下端, 基本の長さ, 裾の長さ)` の共通部品にしてある。
新しい種は、胴・頭・牙や角の数十行を書くだけで足せる。

**毛皮は、表面の近く（距離0.35以内）だけで揺らぎを引く。**
揺らぎは縦に伸ばした（y方向の周波数を低くした）ノイズで、毛が垂れて見える。
腹の下の帯だけ長くすると、氷期の獣らしい裾になる。

**これまでの種と、らしさの要点。**

| 種 | 背丈 | らしさの要点 |
| --- | --- | --- |
| マンモス | 約3.7m | 高い肩から後ろへ下がる背、丸い頭頂、小さな耳、下へ出て外へ張り出し前で持ち上がって内へ巻く牙 |
| ケサイ | 約2.0m | 地面へ向けて低く構えた頭、横に平たく前へ反る長い角と後ろの小さな角、盛り上がった肩、短い脚 |
| 竜脚類 | 約4.7m | 胴より長い首と尾がどちらも備わること、小さすぎるほど小さい頭、曲げない柱の脚 |
| 角竜 | 約2.5m | 前後に薄く上と横へ広い襟飾り、目の上の2本と鼻の上の1本、低く構えた体 |
| 獣脚類 | 約2.9m | 地面と平行に近い背骨、腰を挟んで釣り合う頭と尾、小さすぎるほど小さい前あし |

**中生代の3種は毛皮を通さない。** 鱗の獣なので、表面の揺らぎを引かない。
そのぶん面は4,500で足り、氷期の2種（6,000〜7,000）より軽い。

**確かめ方。** この作業環境に画面がなくても、`npm i gl pngjs` と `xvfb-run` で
WebGL を動かせる。シェーダーを通して横・斜め前・正面の3枚を描き、
形の崩れ（牙が棒に見える、脚が短い、顔が筒）を目で拾って直す。

**シェーダーで踏んだ罠。**

- `smoothstep(大, 小, x)` は規格上の動作が決まっていない。`1.0 - smoothstep(小, 大, x)` と書く
- WebGL1 のループは回数を定数で書く。途中で `break` する
- `site/` と同じく外部に依存しない。Googleフォントも読まない

## 2. 同じ式を網目に焼く

`python3 docs/prototypes/bake_creatures.py 出力先` で全種を焼き直せる。
要るものは `numpy`、`scikit-image`、`fast-simplification`。

1. **式を numpy へ移す。** ノイズの hash も同じ式にする。揺らぎの模様が試作と一致する
2. **格子で評価する。** 間隔はマンモス2.8cm、ケサイ2.0cm。毛の模様は10cm周期なので、これより粗いと毛が消える
3. **地面の下を切る。** `max(距離, -y)` で足の裏をy=0の平面にする
4. **表面を取り出す**（marching cubes）。15〜17万面になる
5. **面を減らす。** マンモス7,000面、ケサイ6,000面。Gobkit の恐竜（520〜982面）より細かいが、毛皮にはこれくらい要る
6. **材質を2つに分ける。** 面の重心で胴と牙のどちらが近いかを見て、`creature` と `tusk` に振る
7. **向きを Unity に合わせる。** 試作の（前, 上, 横）を Unity の（横, 上, 前）へ。
   **Unity は OBJ の X を反転して読む**ので、書くときに X を反転しておく
8. **立ち姿で固める。** 地表の生きものは動かさない。対角の脚を少し前後にずらす

**確かめ方。** 焼いた OBJ を読み、X を反転して（Unity と同じ読み方で）横と斜めから描く。
頭が+Z、足の裏がy=0、毛の模様が残っていることを見る。

## 3. Unity の地表へ置く

置き場は `Resources/Nature/`。名前は `sdf_` で始める。コードの変更は3か所だけ。

| 変更 | 理由 |
| --- | --- |
| `RoleFromMaterial` で `creature` を「生きもの」、`tusk` を「牙」の役にする | 分からない材質名は岩の色で塗られる。牙を胴と同じ色にすると体に沈む |
| 大きさの基準を背の高さにする（`sdf_`） | 「いちばん長い辺の6割」を使うと、長くて低い獣が小さくなる |
| 牙のある獣の分岐で、`TryModel("sdf_…")` を先に試す。読めなければ手組みへ戻る | 素材が欠けても場面が壊れない |

**種を混ぜる。** 氷期はマンモス6割・ケサイ4割。1種だけ並べると複製に見える。
ケサイの背丈はマンモスの0.54倍（焼いた網目の高さの比）を掛けて渡す。

**`.meta` は Unity で開いたときに作られる。** それもコミットする。

### 置いたあとの確かめ方

**Unity を動かせない環境では、近似の絵で先に見る。** 同じ遠景写真
（`Resources/Sky/`）、時代の色（`SurfaceCatalog.cs`）、カメラの値（`AimAtCreatures`）、
撒き方（`ScatterNear`）で描く。配置の乱数・影・照明は一致しないので、目安にとどめる。

**最後は Unity で10時代を書き出して確かめる。** 近似の絵は代わりにならない。

**Unity で確かめた（2026年9月21日）。** Unity 6000.4.8f1 をバッチモードで走らせ、
`SurfaceProbe` から10時代32枚を書き出した。コンパイルエラーは無い。

| 見たところ | 結果 |
| --- | --- |
| 向き | 頭が前を向く。倒れない |
| 足の裏 | 雪の面に接する。埋まらない |
| 大きさ | マンモスとケサイの差が付く。0.54倍の指定どおり |
| 毛皮 | **輪郭としては出る。**裾の垂れと肩の盛り上がりが読める |
| 牙・角 | 形は出る。ただし下記 |

**牙が胴に溶ける件は、実際に起きていた。** 手前の個体では牙が体と同じ色に沈み、
輪郭が追えない。いちばん奥の個体だけ、雪を背にしたぶん牙が見えていた。
**背景の明るさ次第で見えたり見えなかったりする**ということになる。
牙を明るくするかは、まだ決めていない。

`.meta` は Unity がこのとき作った。手順書のとおりコミットしてある。

**近似の絵で分かったこと（2026年9月21日）。**

- 今のカメラ（38m手前・高さ8m）では獣が45〜70m先に立ち、**毛皮の凹凸は見えない。** 読めるのは輪郭（裾・牙・角）
- 10m前後まで寄ると、毛の流れと裾がはっきり見える
- **牙も胴と同じ色で塗られるので、体に溶けて見えにくい。** 牙を明るくするかは未決
